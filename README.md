# Gym Log

An offline Android workout tracker. Log sets, reps and weight per exercise between sets, see whether each lift is actually getting stronger, and export everything as JSON or CSV whenever you want to look at it elsewhere or hand it to an AI agent.

- **Fully offline.** No account, no server, no internet needed. Data lives in the app's private storage on your phone.
- **Five categories:** Legs, Arms & Shoulders, Pull, Push, Abs, with 26 starter exercises. Add or remove your own.
- **Fast logging.** Pick exercise → sets/reps/weight with big +/− buttons → **Add sets**. It pre-fills from your last session and shows "Last: 3×8 @ 60 kg · Best: 65 kg × 8". Logging a new best gives a 🏆 PR alert.
- **Progress screen** built around the questions you have at the gym (see below).
- **Backup & export** to JSON (full backup, self-describing for agents) or CSV (one row per set), through Android's share sheet: Drive, Gmail, Files, WhatsApp, etc. **Restore** from a JSON backup.

## Install on your phone

Every push to `main` builds a signed APK with GitHub Actions and publishes it under **Releases**.

1. On your phone, open this repo → **Releases** → latest build → download **gym-log.apk**
   (direct link: `https://github.com/<you>/<repo>/releases/latest/download/gym-log.apk`).
2. Open the file. Android will ask to allow installs from your browser/Files app the first time; allow it.
3. Open **Gym Log**.

Updating: install a newer APK over the old one. Your data is kept because every build is signed with the same key (`android/app/gymlog-release.jks`). **Don't uninstall** to update. Uninstalling deletes the log, so export a backup first if you ever need to.

## The Progress screen

| Section | What it answers |
|---|---|
| **This week** | Workouts done vs your weekly goal, which days you trained, sets per category vs target (default 10 sets/week, editable in **Goals**), and when each category was last trained. |
| **Next up** | The category furthest behind its weekly target that you've gone longest without training: what to hit today. |
| **Week streak / PRs in 30 days / lifts improving / need attention** | Headline check that you're showing up and progressing. |
| **Recent PRs** | Every new personal best in the last 30 days and how much it beat the previous best by. |
| **Your lifts** | Each exercise with a strength sparkline, a status and the change vs the previous 4 weeks. Tap one for best set, est. 1RM, a chart, recent sessions and a tip. |
| **Consistency** | 16-week heatmap of training days. |

**Strength** = estimated 1-rep max of the best set each session, `weight × (1 + reps / 30)` (Epley), so 80 kg × 8 and 90 kg × 5 compare fairly. Bodyweight exercises (weight 0) track max reps. For timed holds like Plank, log seconds as reps.

**Status** per lift:
- **Improving**: a PR in one of the last 2 sessions.
- **Holding**: no PR for 2–3 sessions (normal).
- **Stalled**: 4+ sessions without a PR. Time to change something.
- **Dropping**: latest session is 8%+ below your best.
- **New**: fewer than 3 sessions logged.

## Export format

JSON (`gym-log-YYYY-MM-DD.json`) contains a plain-English `description` of the fields, the category and exercise lists, and one entry per set:

```json
{ "date": "2026-10-24", "exercise": "Squat", "category": "Legs", "set": 1, "weight_kg": 100, "reps": 5 }
```

CSV (`gym-log-YYYY-MM-DD.csv`) has the same rows: `date,category,exercise,set,weight_kg,reps`.

**Restore from JSON backup** replaces everything on the phone with the file's contents. Use it to move to a new phone.

## Developing

```bash
npm install
npm run serve          # try the app in a desktop browser at http://localhost:8000
                       # (use DevTools' phone view; data is stored in that browser)
```

To build the APK locally you need Android Studio (or the Android SDK) and JDK 21:

```bash
npm run build:apk      # → android/app/build/outputs/apk/release/app-release.apk
```

After changing the icon images in `assets/`, run `npm run icons`.

### Signing key
The repo includes a signing key with a simple password so builds are reproducible and updates install cleanly. That's fine for a personal app; if the repo is public and you'd rather keep the key private, create your own keystore, store it as a GitHub secret, and set `GYMLOG_KEYSTORE` / `GYMLOG_KEYSTORE_PASSWORD` in the workflow. Note that switching keys means one uninstall/reinstall, so export a backup first.
